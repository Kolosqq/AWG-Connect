---
name: awg-regression
description: Verify AWG Connect VPN connection, Windows routing, app and site split tunneling, and normal or Strict Kill Switch behavior.
---

- Select checks by changed behavior. Use the target and CTest names in `client/tests/CMakeLists.txt` and the settings and split tunneling suite in `.github/workflows/windows-split-tunneling.yml`. Run offline tests with `QT_QPA_PLATFORM=offscreen` and an unused local `AMNEZIA_TEST_IPC_URL`, as in CI. Run `WindowsAppPolicyTest` with WFP/registry changes only through its isolated Windows CI job. Use `windows-wfp-policy.yml` for folder matching changes. Count skips separately from passes.
- For real traffic, use a disposable Windows VM with the matching installer, service and driver. Establish the guest's direct baseline and test two distinct processes. Use `deploy/windows/Test-PositiveSplitTunnel.ps1 -Action Prepare`, select only its VPN probe, then use `-Action Probe -ExpectedDirectIp <baseline>`. Check a normal full-tunnel connection, existing exclude and site split behavior, and inclusion with AWG/WireGuard, IPv4 default AllowedIPs and site split off. Compare selected traffic against a known VPN exit as well. The probe only compares the two exits and checks the direct reference. Cover executable, nested folder, new executable before refresh, running process, and empty selection where affected.
- Check both Kill Switch modes while connecting, after manual disconnect, after unexpected tunnel loss with the service running, and after reconnect. Normal mode releases selected apps after manual disconnect and holds them after unexpected loss. Strict mode keeps selected apps blocked while disconnected. Unselected apps stay direct. Check policy removal on disable, no global block for empty selection, and route, DNS and firewall cleanup after failure and teardown. WFP policy is tied to the service session. Service termination and tunnel loss are separate cases.
- For a Windows release, run both automated and VM checks above. Cover native and managed configs and exercise IPv4, IPv6, system DNS, UDP/QUIC, and adapter changes for relevant traffic paths. For shared changes, cover affected self-hosted, Premium/Free and native paths. Keep traffic probes and reports free of credentials and private addresses. Record results by candidate SHA and distinguish policy tests from real-driver traffic checks.
