# Windows x64 release

1. Identify the candidate commit and the latest fork tag and GitHub Release. The fork's public version and `v<version>` tag are distinct from upstream's `AMNEZIAVPN_VERSION` in `CMakeLists.txt`. Agree on the public version and stable or prerelease status before changing release metadata. Check the installer metadata, asset name, and download links in `README.md` and `README_RU.md` against that version. Update the project changelog if present and prepare release notes from verified changes.
2. Build the exact candidate SHA with `.github/workflows/windows-split-tunneling.yml` or reproduce its configure, build, CTest, and CPack IFW steps. Require successful Windows regression CI for that SHA, including its isolated WFP test, and use the `windows-split-tunneling-installer` artifact from that run. Confirm the client and service came from the same build. Check the SHA of any manually dispatched run before using its artifact.
3. Run the full [VPN regression matrix](vpn-regression.md), including real-driver VM checks on that installer. Smoke-test clean install, upgrade with retained settings, and uninstall cleanup. Check the installer and driver signatures with `Get-AuthenticodeSignature` and record actual signing status. Compute the final asset hash with `Get-FileHash -Algorithm SHA256`. Stop on failed or missing required checks and report the gap.
4. Present the candidate SHA, version/tag, asset name and SHA-256, release notes, signing status and verification results for approval. Wait for explicit approval before creating even a draft GitHub Release or pushing a release tag. After approval for that candidate, verify that the tag and release are unused or already point at the approved candidate. Publish to `Kolosqq/AWG-Connect` with the verified installer and checksum, targeting the exact SHA and approved release type. Check the published tag, assets and download hash. If a remote write partially succeeds, inspect remote state before retrying.
